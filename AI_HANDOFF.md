# Передача реализации быстрым моделям

## Постоянные правила

1. Дай модели ровно одну задачу из `BACKLOG.md`.
2. Передай README и только релевантные docs; не проси «сделать весь проект».
3. Запрети менять публичные контракты без явного ADR/обновления документации.
4. Требуй сначала прочитать существующий код и тесты, затем перечислить затрагиваемые файлы.
5. Требуй полный код, тесты, команды проверки и краткий changelog.
6. После ответа запускай тесты другой моделью/агентом; не принимай заявленное «работает» без выполнения.

## Универсальный промпт реализации

```text
Ты реализуешь задачу <ID и текст> в проекте HH Analytics Market.
Контекст: README.md, <релевантный doc>, BACKLOG.md.
Соблюдай текущую архитектуру, Python 3.12, type hints, docstrings для публичного API,
structured logging, отсутствие секретов, детерминированность и идемпотентность.

Сначала:
1) прочитай существующие файлы;
2) кратко укажи контракт задачи, зависимости и список изменяемых файлов;
3) не расширяй scope.

Затем реализуй задачу полностью. Добавь unit/integration тесты по acceptance criteria.
В конце выдай: изменённые файлы, команды запуска, фактические результаты тестов,
оставшиеся ограничения. Не переходи к следующей backlog-задаче.
```

## Промпт ревью

```text
Проведи read-only ревью изменений для задачи <ID>. Сверь с acceptance criteria,
архитектурными инвариантами и data model. Ищи: потерю provenance, неидемпотентность,
data leakage, неверную обработку NULL/зарплат, слабые тесты, секреты и недетерминизм.
Сначала перечисли проблемы по severity с файлами/строками, затем пропущенные тесты.
Не переписывай код, пока отдельно не попросят исправить.
```

## Контрольный чек после каждой задачи

- Scope совпадает с одним ID.
- Acceptance доказан тестом/командой.
- Нет placeholders, silently swallowed exceptions и hardcoded secrets.
- Новые таблицы/метрики документированы.
- Воспроизводимость не зависит от локального состояния.
- BACKLOG отмечается завершённым только после независимой проверки.
